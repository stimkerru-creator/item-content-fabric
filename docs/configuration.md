# Форматы для разработчиков

Обычному пользователю достаточно [редактора](editor.md). Он сам создаёт конфигурацию,
resource pack и при необходимости datapack. Этот документ нужен авторам интеграций и сборок.

## Конфигурация игры

Файл: `config/item-content/items.json`. Версия `2` обозначает формат файла, а не Minecraft,
версию предмета или номер рецепта. Формат `1` продолжает читаться.

```json
{
  "version": 2,
  "groups": [{"id": "itemcontent:metallurgy", "name": "Металлургия", "icon": "minecraft:copper_ingot"}],
  "items": [
    {
      "id": "itemcontent:bronze_sword",
      "name": "Бронзовый меч",
      "type": "itemcontent:sword",
      "group": "itemcontent:metallurgy",
      "appearance": "minecraft:iron_sword",
      "custom_model": false,
      "max_count": 1,
      "fireproof": false,
      "existing": false,
      "properties": {"durability": 750, "attack_damage": 9, "attack_speed": 2.5, "repair_item": "minecraft:copper_ingot"}
    }
  ]
}
```

| Ключ | Назначение |
|---|---|
| id | ID нового предмета в `itemcontent`; без namespace он добавляется автоматически |
| name | Отображаемое имя, 1–128 символов |
| type | ID зарегистрированного типа; по умолчанию `itemcontent:item` |
| group | ID вкладки креатива; по умолчанию категория типа |
| appearance | ID исходной модели; для новых блоков — ID с блочной моделью |
| custom_model | `true`: ресурсы собственной модели; `false`: выбранная готовая модель |
| max_count | Стак 1–99; изнашиваемый предмет требует 1 |
| fireproof | Устойчивость выброшенного предмета к огню и лаве |
| existing | Только при `true` настраивается уже зарегистрированный ID; новый объект не создаётся |
| properties | Настройки известного типа; у нового объекта пропуски заполняются значениями по умолчанию |

Встроенные типы: `item`, `food`, `sword`, `pickaxe`, `axe`, `shovel`, `hoe`, `bow`, `crossbow`,
`armor`, `block`, `decorative_chest`, `decorative_furnace` в namespace `itemcontent`.
Полные поля и диапазоны определены в `common/src/main/java/dev/itemcontent/definition/BuiltinTypes.java`
и показаны формами редактора. Неизвестные типы, поля, неверные диапазоны, повторные ID отклоняются.
Нормальные прочность, еда и урон — настройки нативного поведения. Индивидуальные числовые массивы/формулы сюда не входят.

Для существующего предмета укажите `existing:true`, исходный ID и поддерживаемый тип.
`group:"itemcontent:keep"` сохраняет исходные вкладки. Другой group заменяет их выбранной категорией.
Тип запрещает редактировать поля с `editExisting=false`; отсутствие настройки не сбрасывает её на defaults.
Режим исходного предмета не заменяет его Java-класс. Эффекты исходной еды сохраняются.

`groups` создаёт свои вкладки только в namespace `itemcontent`; `itemcontent:keep` зарезервирован.
Для групп других модов используйте их существующие ID; они появляются в каталоге реальной игры.
Клиент и сервер должны иметь одинаковый файл, мод и поставщиков поведения до соединения.
Изменения применяются после перезапуска. Registry не расширяется при работающем мире.

## Ресурсы

Экспорт создаёт стандартный pack_format 15 для Minecraft 1.20.1:

```text
resourcepacks/item-content/
├─ pack.mcmeta
└─ assets/itemcontent/
   ├─ models/item/<id>.json
   ├─ textures/item/<id>.png
   ├─ models/block/<id>.json          # для блоков
   ├─ textures/block/<id>.png
   ├─ blockstates/<id>.json
   ├─ textures/models/armor/<id>_layer_1.png
   └─ lang/ru_ru.json
```

Теги добычи создаются отдельно в `datapacks/item-content/data/minecraft/tags/blocks`.
Datapack устанавливается в каждый мир; resource pack — на клиенты.
Собственные функции печи/инвентаря/оружия реализуются типом расширения, не файлом модели.
Модель неизвестного ресурса может отображаться как missing-model; используйте существующий ID источника.

## Файл редактора и каталог игры

`.icproject`: `editorVersion:2`, массив `items`, схемы `types`, собственные `groups`.
Это редактируемый исходник с путями к PNG, не игровой рецепт и не самостоятельный мод.
Версия 1 читается; прежние индивидуальные поля не применяются, исходник резервируется перед сохранением.

`config/item-content/catalog.json`: `version:1`, описания типов, группы и снимок реестра предметов.
Это отдельный формат каталога. Он создаётся на клиенте после входа в мир или командой `/itemcontent catalog`.
Писать эти служебные файлы вручную не требуется. Изменения каталога не изменяют игру.

Ограничения: конфигурация/список 4 МиБ и 4096 определений, до 256 своих вкладок;
каталог 32 МиБ и 65536 записей, PNG-иконки каталога до 1 МиБ каждая и суммарно 64 МиБ на выгрузку.
Эти пределы служат защитой от ошибочных файлов и не являются результатами нагрузочного тестирования.
