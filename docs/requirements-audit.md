# Соответствие требованиям: Item Content 1.0.3

Дата проверки: 10 ноября 2026 года. Это проверка исходников, автоматических сценариев
и упаковки текущего проекта; она не является независимой внешней сертификацией.
Формулы и ST Market к предмету этой проверки не относятся.

## Назначение и границы

Второй самостоятельный репозиторий создаёт реальные типы предметов для Minecraft 1.20.1 / Fabric.
Первый проект Item Parameters отвечает за индивидуальные характеристики и производственные формулы.
Редактор второго проекта не содержит вычислителя, рецептов или нового станка.
Мод второго проекта может работать без первого; дополнительная интеграция передаёт начальные параметры
через существующий каталог первого проекта.

## Требования и реализация

| Требование | Реализация и подтверждение |
|---|---|
| Отдельный проект и Git | Собственный корень, история Git, сборка, документация и CI; соседний репозиторий для сборки не требуется |
| Создать предмет без Java и ручного JSON | Swing-приложение: добавить, указать название и ID, выбрать изображение, экспортировать |
| Реальный собственный ID вместо заранее заготовленного слота | Регистрация `itemcontent:<имя>` в реестре Minecraft до открытия мира; нет пула заглушек |
| Не занимать ID других модов | Разрешено собственное пространство `itemcontent`; повтор уже зарегистрированного ID вызывает ошибку |
| Своя картинка | Выбор PNG, предпросмотр, копирование байтов, создание модели и resource pack при экспорте |
| Готовая внешность | Ссылка на модель существующего предмета; для модели чужого мода этот мод должен быть на клиенте |
| Свойства предмета | Название, размер стака, устойчивость к огню и лаве |
| Начальные характеристики первого проекта | Необязательная таблица полей; точные int32-сотые, ID, начальные значения и диапазоны |
| Не дублировать определения параметров | Совпадающее описание первого проекта используется без дублирования; расхождение останавливает загрузку, пользовательские файлы сохраняются |
| Сохранить работу | `.icproject`, открытие и сохранение, подтверждение несохранённых изменений |
| Понятный запуск | Готовый ZIP с Java-приложением, Windows-запускателем и примером; исходники отдельно собираются Gradle Wrapper |
| Соблюдение лицензий | MIT собственного кода; Gson и полный Apache 2.0 в редакторе, уведомления в обоих JAR |
| Использование в производственных цепочках | Новый ID указывается во входах/выходах первого редактора; вычислитель второго мода отсутствует |

## Как проходит работа пользователя

1. Распаковать готовый ZIP и запустить `run-editor.bat` с Java 17+.
2. Открыть пример `examples/steel-plate.icproject` или создать предмет слева.
3. Ввести игровое название, постоянный ID; выбрать PNG либо готовую модель.
4. Необязательные числовые характеристики задать здесь или целиком в первом редакторе.
5. Сохранить проект; экспортировать в новую пустую папку.
6. Установить мод и одинаковое описание на сервер и клиенты; resource pack включить на клиентах.
7. Указать полученный ID в рецепте первого проекта.

В интерфейсе есть список предметов слева, карточка текущего предмета справа и отдельная
необязательная таблица параметров. Формат не требует ручного составления JSON.
Пошаговые действия, значения полей и пример приведены в [инструкции](editor.md).
Удобство для конкретного автора сборки окончательно проверяется его практическим сценарием;
одни unit-тесты не доказывают понятность интерфейса каждому пользователю.

## Ошибки, исправленные при этой проверке

- Дробные и слишком большие `max_count` больше не преобразуются молча в другое целое.
- Неверные типы JSON, повтор ID параметра и опечатки в ключах полей отклоняются при загрузке.
- Ошибочные структуры JSON приводят к диагностической `IOException` из парсера.
- После удаления параметра добавление следующего не создаёт повторяющийся ID.
- Переключение предметов сохраняет незавершённое редактирование числовой ячейки у правильного предмета.
- Предпросмотр PNG сохраняет пропорции исходного изображения.
- Готовая поставка включает редактор и запускатель; пользователю не нужно собирать код.
- В JAR мода добавлены лицензия собственного кода и уведомления о зависимостях.

## Быстродействие и объём

Регистрация предметов и создание каталога выполняются при старте, а не каждый игровой тик.
У мода нет собственного tick-цикла и расчёта формул. Характеристики экземпляров хранит первый мод;
этот мод хранит определения типов предметов. Модели разрешаются при загрузке ресурсов клиента.
Desktop-экспорт работает отдельно от игрового процесса.

Текущие защитные пределы: 4096 типов предметов в каталоге, 4 МиБ конфигурации/проекта,
4096 полей одного типа и 16 МиБ/4096×4096 для одной PNG. Достижимость пределов одновременно
не гарантируется: раньше может сработать ограничение общего размера файла.
Это границы формата, а не результат нагрузочного теста. Замеры для 10 000 новых типов предметов
не выполнены и текущий лимит регистрации такого числа не допускает.
Большое число разных числовых вариантов одного ID — отдельная задача первого проекта.

## Совместимость, безопасность и оставшиеся границы

- Клиент и сервер должны заранее иметь одинаковые определения предметов. Автоматической доставки
  каталога и отдельного протокола проверки его полного совпадения этот мод не реализует.
- Список ID меняется после перезапуска; добавление registry item в уже работающий мир не поддержано.
- Собственное пространство имён предотвращает присвоение чужих ID, но не доказывает совместимость
  со всеми модами. Проверялся Fabric и соседний Item Parameters; произвольные модпаки не тестировались.
- Здесь нет сетевого редактора или пакетов, позволяющих игроку менять серверный каталог.
  Конфигурацию изменяет администратор через файлы. Это не аудит безопасности всего сервера.
- Для другого загрузчика Minecraft требуется совместимая реализация; совпадения версии игры недостаточно.
- Изображения хранятся в проекте как ссылки на исходные файлы. Для переноса `.icproject` на другой ПК
  перенесите PNG и выберите их заново. Экспорт уже содержит отдельные копии изображений.
- Существующая сторонняя модель не проверяется desktop-приложением на наличие: её разрешает клиент Minecraft.
- Операции чтения больших PNG и экспорта выполняются в потоке интерфейса. Для очень крупных каталогов
  фоновый экспорт и поиск по списку остаются возможным улучшением, а не реализованной возможностью.
- Экспорт создаётся в новой/пустой папке. Прямая установка с резервным копированием в игру, как в первом
  редакторе, здесь отсутствует: готовые каталоги копируются по инструкции.
- Собственная добыча, крафты, GUI станков, новые блоки и произвольные игровые свойства предметов
  не входят в этот конструктор. Их подключают соответствующие моды и адаптеры.

Сводка фактически выполненных проверок — в [validation.md](validation.md).
